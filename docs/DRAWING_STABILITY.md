# 绘图页面内存与草稿恢复修复（2026-10-29）

用户报告绘制结构和编辑载荷时，Chromium 页面出现 Out of Memory。源码中确认了两处可持续放大内存/工作量的路径：

- drawingSnapshot 每次 JSON.stringify 整个 scene，包含 analysisNodes、mesh 和节点计算数据。每次输入前后均序列化，100条撤回记录会保存100份大型网格字符串，选择/平移时也曾无条件创建完整快照。
- 绘图 render() 在动画启用时每次调用都 requestAnimationFrame(render)。鼠标移动、载荷输入和其他主动重绘会各自添加动画链；原先取消动画只取消最后一帧。

本次改为：撤回只保存可编辑场景，排除网格、计算节点和布点数据；总内存按字符串 UTF-16 长度限制到16 MiB，同时保留最多100步。连续同一载荷同一字段750ms内的输入合并为一个撤回步骤。只有进入几何拖动才捕获拖动快照。载荷撤回保留当前网格；几何撤回保留单份网格并标记过期，避免用不匹配的几何继续计算。超出整个撤回预算的单步不会被保留。

绘图动画采用唯一待执行帧，回调开始即清除帧句柄；主动重绘不再添加并行动画链。离开绘图页后不继续调度绘图动画。

草稿在每次有效绘图命令、载荷修改、撤回、导入或清空后触发保存，300ms合并一次，最多一个保存请求在途，只发送最新待保存内容。保存到 calculation-data/recovery/drawing-draft.json，先写临时文件再替换。以编辑时间阻止迟到的旧请求覆盖较新数据。项目文件不依赖桌面启动端口。浏览器也缓存小型草稿，使用工作目录标识隔离缓存。保存失败时页面显示提示，不静默假装成功。

启动时恢复几何、材料快照、载荷和未完成绘图步骤，不恢复庞大的网格或计算结果，网格需要重新生成。启动读取期间用户已经开始编辑时，不用旧草稿覆盖新操作。清空结构会保存为空草稿，重要的长期版本仍应通过“保存 JSON”保留。恢复的是最近完成保存的草稿，不能追溯补救安装本修复前未持久化的数据；突然终止时最后尚未保存的约300ms操作仍可能丢失。服务端接受的自动保存上限8MiB，超限会显示保存失败并提示手动保存JSON。

验证：

- 120项相关测试通过，包括绘图/撤回、连续输入合并、动画调度、草稿存取/重启、异步读取竞争、过期写入、静力求解和强度准则回归。
- 128MiB JS堆限制下，50,000计算节点+100,000单元模型执行1,000次载荷编辑，100条撤回记录共44,600字节，强制GC后新增堆占用约65,224字节（具体值随运行变化），同一网格保持引用。可运行 node --expose-gc --max-old-space-size=128 scripts/check-drawing-memory.cjs 复查。
- 5,000次事件重绘加50轮动画回调始终只有1条待执行动画帧。
- 隔离目录中启动实际页面，绘制矩形、创建点载荷并连续调整到3000N，确认磁盘草稿值后重新加载，页面恢复4个几何节点、4条边界、1个区域及3000N点载荷。

需要关闭并重新打开 TENSORA，以便本地 Node 服务加载新增恢复接口。原桌面启动器直接使用程序目录中的 server.js，无需重新编译启动器或计算核心。
